# Командный курс: «Создание игры Don't Starve Lite с помощью JavaScript и нейросетей»
## Полное руководство для ментора (компас проекта)

---

## 1. Общие положения

### Цель курса
За **30 занятий** (каждое по 1.5 часа) команда из ~20 студентов разработает упрощённую веб‑версию игры в жанре **survival** (по мотивам *Don't Starve*), используя **JavaScript** и **генеративные нейросети** для создания графики, звуков, текстов и помощи в коде.  
Итоговый продукт будет опубликован на **GitHub Pages** и представлен в виде презентации.

**Ключевые механики MVP:**
- Процедурно генерируемая карта (сетка тайлов: трава, лес, камни).
- Управляемый персонаж (движение WASD).
- Сбор ресурсов (деревья, камни, ягоды).
- Инвентарь и базовый крафт (топор, кирка, факел).
- Враги (паук, гончая), которые атакуют игрока.
- Показатели голода и здоровья, уменьшающиеся со временем и при атаках.
- Цель: продержаться как можно дольше.

### Командная структура
Студенты делятся на **6 постоянных команд**, каждая отвечает за свой аспект проекта. Вклад каждого уникален и интегрируется через Git.

| Команда                | Ответственность                                                                 | Рекомендуемый размер |
|------------------------|---------------------------------------------------------------------------------|----------------------|
| **Core Mechanics**     | Классы игрока, ресурсов, предметов, крафта, врагов; физика сбора и атак.       | 4                    |
| **Game State & UI**    | Инвентарь, полоски голода/здоровья, интерфейс крафта, отображение карты.       | 4                    |
| **AI & Balance**       | Поведение врагов, генерация волн, баланс ресурсов и голода.                    | 3                    |
| **Assets & Graphics**  | Генерация спрайтов (персонаж, ресурсы, враги, тайлы), иконки предметов.         | 4                    |
| **Sound & Effects**    | Звуки окружения, сбора, атак, крафта; визуальные эффекты (вспышки, частицы).   | 3                    |
| **Integration & QA**   | Генерация карты, настройка Git, сборка, деплой, тестирование, документация.     | 2                    |

> **Важно:** каждая команда выбирает **лида**, который координирует работу внутри группы и участвует в общих синхронизациях.

### Инструменты и технологии
- **Язык:** JavaScript (ES6+), HTML5 Canvas, CSS.
- **Среда разработки:** VS Code (рекомендуется) или любой текстовый редактор.
- **Система контроля версий:** Git, GitHub (репозиторий, issues, projects, pull requests).
- **API нейросетей:** Hugging Face Inference API (бесплатный токен). Модели:
  - **Текст:** `gpt2`, `microsoft/DialoGPT-medium` (или платные аналоги).
  - **Изображения:** `stabilityai/stable-diffusion-2-1`, `runwayml/stable-diffusion-v1-5`.
  - **Звуки:** можно использовать `facebook/musicgen-small` (но требует времени) либо готовые библиотеки звуков.
- **Деплой:** GitHub Pages.

### Правила работы с Git и GitHub
- **Основные ветки:**
  - `main` – только стабильные версии (защищена, требуется PR и ревью).
  - `develop` – ветка разработки, куда мёржатся все фичи.
- Каждая задача оформляется как **issue** с меткой команды и приоритетом.
- Для выполнения задачи создаётся **фича‑ветка** от `develop` с именем `feature/краткое-описание`.
- После завершения работы открывается **pull request** в `develop`. В PR обязательно указывается, что сделано, и ссылка на issue.
- **Code review:** минимум один проверяющий из другой команды (ментор назначает). Замечания исправляются, затем PR мёржится.
- Все изменения должны быть работоспособны и не ломать существующий код.

### Использование нейросетей
- Нейросети используются как **инструмент**, а не замена программированию.
- Ученики формулируют промпты, анализируют результаты, при необходимости повторяют запросы.
- Все сгенерированные материалы (изображения, тексты, звуки) сохраняются в соответствующие папки (`assets/images/`, `assets/sounds/`, `data/`) и добавляются в Git.
- В случае недоступности API предусмотрены **запасные варианты** (заглушки).

## 2. Подготовительный этап (до начала курса)

**Ментор:**
1. Создаёт репозиторий `dont-starve-lite` с начальной структурой:
   ```
   /
   ├── index.html
   ├── style.css
   ├── js/
   │   └── main.js
   ├── assets/
   │   ├── images/
   │   └── sounds/
   ├── data/
   └── README.md
   ```
2. Настраивает защиту ветки `main` (требовать PR, 1 одобрение).
3. Создаёт доску проектов GitHub с колонками: **To do**, **In progress**, **Review**, **Done**.
4. Готовит шаблоны issues (с метками команд).
5. Знакомится с API Hugging Face, получает токен (можно создать общий для всех).

## 4. Приложения

### Приложение 1. Работа с Hugging Face API

**Получение токена:**
1. Зарегистрироваться на [huggingface.co](https://huggingface.co/).
2. Зайти в **Settings** → **Access Tokens** → **New token** (role: **read**).
3. Скопировать токен.

**Пример запроса к текстовой модели:**
```javascript
async function queryText(prompt, model = 'gpt2') {
  const response = await fetch(
    `https://api-inference.huggingface.co/models/${model}`,
    {
      headers: { Authorization: `Bearer ${YOUR_TOKEN}` },
      method: 'POST',
      body: JSON.stringify({ inputs: prompt }),
    }
  );
  const result = await response.json();
  return result[0]?.generated_text || result.error;
}
```

**Пример запроса к модели изображений:**
```javascript
async function queryImage(prompt, model = 'stabilityai/stable-diffusion-2-1') {
  const response = await fetch(
    `https://api-inference.huggingface.co/models/${model}`,
    {
      headers: { Authorization: `Bearer ${YOUR_TOKEN}` },
      method: 'POST',
      body: JSON.stringify({ inputs: prompt }),
    }
  );
  const blob = await response.blob();
  return URL.createObjectURL(blob);
}
```

**Примечание:** Некоторые модели могут требовать больше времени, ответ может прийти не сразу. В документации Hugging Face есть параметр `options={wait_for_model:true}`.
