### 3. Клонирование репозитория и настройка Git (20 минут)

**Теория (5 минут):**
Показываю схему веток на доске:
```
main
 └── develop (основная ветка разработки)
      └── feature/название-задачи (ваша ветка)
           └── pull request обратно в develop
```

**Практика (15 минут):**

Выполняем по шагам:

```bash
# Шаг 1. Клонируем репозиторий
git clone https://github.com/[название-организации]/clash-royale-lite.git
cd clash-royale-lite

# Шаг 2. Проверяем ветки
git branch -a          # покажет все ветки (локальные и удалённые)
git checkout develop   # переключаемся на develop

# Шаг 3. Создаём свою ветку для первого задания
# Формат: feature/hello-название-команды
# Например: feature/hello-core-mechanics
git checkout -b feature/hello-название-команды

# Шаг 4. Проверяем, что мы в нужной ветке
git branch             # звёздочка должна быть у вашей новой ветки
```

**Если возникают ошибки:**
- `Permission denied` — не добавили SSH-ключ (помогаем индивидуально)
- `Repository not found` — не приняли приглашение в организацию

### 5. Первый коммит и Pull Request (15 минут)

**Пошаговая инструкция (дублирую на экране):**

```bash
# Шаг 1. Проверяем, что мы в своей ветке
git branch

# Шаг 2. Добавляем все изменения
git add .

# Шаг 3. Делаем коммит
git commit -m "feat: инициализация команды [название]"

# Шаг 4. Пушим в удалённый репозиторий
# ВНИМАНИЕ: команда ниже выполняется ТОЛЬКО при первом пуше ветки
git push --set-upstream origin feature/hello-название-команды
```

**Как открыть Pull Request:**

1. Заходим на GitHub в наш репозиторий
2. Видим жёлтую плашку: "feature/hello-... had recent pushes" → нажимаем "Compare & pull request"
3. Заполняем описание PR:
   ```
   ## Что сделано
   - Добавлен файл core.js с приветствием
   - Подключен скрипт в index.html
   
   ## Связанные issues
   Closes #1 (номер issue, если создавали)
   
   ## Чек-лист
   - [x] Код работает локально
   - [x] Нет конфликтов с develop
   ```
4. Слева выбираем `base: develop` ← `compare: feature/...`
5. Назначаем ревьювера (например, лида Integration & QA)
6. Нажимаем "Create pull request"

## 🚨 Важные моменты и частые проблемы

### Проблема 1: Не могу запушить
```
error: failed to push some refs to...
```
**Решение:** Кто-то уже запушил изменения в develop? Обновите свою ветку:
```bash
git checkout develop
git pull origin develop
git checkout feature/...
git merge develop
# решаем конфликты, если есть
git push
```

### Проблема 2: Забыл переключиться на develop перед созданием ветки
**Решение:** Ничего страшного, но лучше пересоздать ветку правильно.

### Проблема 3: PR в main, а не в develop
**Решение:** Прямо в PR на GitHub можно изменить base ветку (кнопка Edit рядом с названием).

### Проблема 4: Git не видит удалённые ветки
**Решение:**
```bash
git fetch --all
```
