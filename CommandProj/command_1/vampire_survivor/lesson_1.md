## 1. Введение в проект (15 минут)

### Что мы будем делать?
Мы создадим упрощённую веб-версию игры Vampire Survivors. Это игра в жанре bullet heaven, где персонаж автоматически атакует орды врагов, собирает опыт и становится сильнее.

**Ключевые механики нашего MVP:**
- Управление персонажем (WASD)
- Автоматическая атака (оружие стреляет само)
- Бесконечные волны врагов
- Сбор кристаллов опыта
- Повышение уровня и выбор улучшений
- Условие поражения (здоровье = 0)

### Командная структура
Мы разделились на 6 команд. Каждая команда отвечает за свою часть проекта:

| Команда | Ответственность | Лид |
|---------|-----------------|-----|
| **Core Mechanics** | Игрок, враги, оружие, коллизии | _назначим_ |
| **Game State & UI** | Интерфейс, меню, отображение | _назначим_ |
| **AI & Balance** | Спавн врагов, сложность, поведение | _назначим_ |
| **Assets & Graphics** | Спрайты, графика, стиль | _назначим_ |
| **Sound & Effects** | Звуки, визуальные эффекты | _назначим_ |
| **Integration & QA** | Сборка, тестирование, деплой | _назначим_ |

> **Важно:** Каждая команда выбирает лида, который будет координировать работу и участвовать в синхронизациях.

## 2. Настройка рабочего окружения (25 минут)

### Шаг 1. Регистрация на GitHub
Если у кого-то ещё нет аккаунта на GitHub — регистрируемся сейчас.

### Шаг 2. Получение доступа к репозиторию
Я добавил всех вас в организацию и в репозиторий. Вы должны получить письмо-приглашение на почту, связанную с GitHub. **Подтвердите приглашение.**

Наш репозиторий: `https://github.com/[организация]/vampire-survivors-lite`

### Шаг 3. Настройка Git локально
Проверяем, что Git установлен:
```bash
git --version
```

Настраиваем имя и почту (они должны совпадать с GitHub):
```bash
git config --global user.name "Ваше Имя"
git config --global user.email "ваша@почта.com"
```

### Шаг 4. Клонирование репозитория
```bash
git clone https://github.com/[организация]/vampire-survivors-lite.git
cd vampire-survivors-lite
```

### Шаг 5. Настройка SSH-ключа (рекомендуется)
Чтобы не вводить пароль при каждом push:
```bash
ssh-keygen -t ed25519 -C "ваша@почта.com"
# Нажимаем Enter на все вопросы
cat ~/.ssh/id_ed25519.pub
```
Копируем вывод и добавляем в GitHub: Settings → SSH and GPG keys → New SSH key

## 3. Наш рабочий процесс в GitHub (15 минут)

### Основные ветки
- **`main`** — только стабильные версии. Сюда нельзя пушить напрямую, только через Pull Request.
- **`develop`** — основная ветка разработки. Все фичи вливаются сюда.

### Как мы работаем с задачами
1. Каждая задача оформляется как **Issue** с меткой команды.
2. Лид команды или я создаю Issue для каждой задачи.
3. Вы берёте задачу в работу и создаёте от `develop` ветку с именем:  
   `feature/краткое-описание`  
   Например: `feature/lesson1-core`

### Как называть коммиты
Пишем осмысленно, на английском или русском. Глагол в начале:
- `Add: функция drawPlayer`
- `Fix: ошибка загрузки скриптов`
- `Update: README.md`

### Pull Request (PR)
Когда задача готова:
1. Пушите ветку в репозиторий
2. Открываете Pull Request в `develop`
3. В описании PR указываете: "Closes #номер_issue"
4. Назначаете ревьювера (меня или другого студента)
5. После одобрения PR вливается в `develop`

## 4. Практика: первый коммит (35 минут)

Сейчас каждая команда выполнит своё задание. Результат — все увидят в консоли приветствие от вашего модуля.

### Общий алгоритм для всех команд:
1. Убедиться, что вы на ветке `develop` и она актуальна:
   ```bash
   git checkout develop
   git pull origin develop
   ```

2. Создать свою ветку для занятия:
   ```bash
   git checkout -b feature/lesson1-название-команды
   # Например: git checkout -b feature/lesson1-core
   ```

3. Выполнить задание (см. ниже для своей команды)

4. Добавить файлы в коммит:
   ```bash
   git add .
   ```

5. Сделать коммит:
   ```bash
   git commit -m "Add: первый коммит команды [название]"
   ```

6. Отправить ветку на GitHub:
   ```bash
   git push origin feature/lesson1-название-команды
   ```

7. Открыть Pull Request в `develop` через интерфейс GitHub

### Задания для команд

#### Команда Core Mechanics
**Задача:** Создать файл `js/core.js` с функцией приветствия.

**Детали:**
1. В папке `js` создать файл `core.js`
2. Написать функцию:
   ```javascript
   function helloCore() {
       console.log("Core Mechanics ready 💪");
   }
   ```
3. Подключить этот файл в `index.html` после `main.js`:
   ```html
   <script src="js/core.js"></script>
   ```
4. В `main.js` вызвать функцию:
   ```javascript
   helloCore();
   ```

#### Команда Assets & Graphics
**Задача:** Создать структуру для графики и проверить загрузку изображения.

**Детали:**
1. Создать папку `assets/images/`
2. Скачать или создать любую картинку размером 64x64 пикселя, сохранить как `placeholder.png` в созданную папку
3. В `index.html` добавить скрытый тег для проверки:
   ```html
   <img src="assets/images/placeholder.png" alt="placeholder" style="display: none;" id="testImage">
   ```
4. Создать файл `js/graphics.js` с функцией:
   ```javascript
   function helloGraphics() {
       const img = document.getElementById('testImage');
       if (img.complete) {
           console.log("Assets & Graphics ready 🖼️ (изображение загружено)");
       } else {
           console.log("Assets & Graphics ready 🖼️");
       }
   }
   ```
5. Подключить `graphics.js` в `index.html` и вызвать `helloGraphics()` в `main.js`

#### Команда Sound & Effects
**Задача:** Создать структуру для звуков и проверить загрузку аудио.

**Детали:**
1. Создать папку `assets/sounds/`
2. Найти любой бесплатный короткий звук (можно с freesound.org) и сохранить как `click.mp3` в созданную папку
3. В `index.html` добавить скрытый аудиоэлемент:
   ```html
   <audio id="testSound" src="assets/sounds/click.mp3" preload="auto"></audio>
   ```
4. Создать файл `js/sound.js` с функцией:
   ```javascript
   function helloSound() {
       const audio = document.getElementById('testSound');
       console.log("Sound & Effects ready 🔊 (звук загружен: " + !!audio + ")");
   }
   ```
5. Подключить `sound.js` в `index.html` и вызвать `helloSound()` в `main.js`

## Часто задаваемые вопросы

**Q: Что делать, если я не успел(а) создать PR?**
A: Ничего страшного. Дома повторяете шаги из раздела 4 и открываете PR. Главное — сделайте это до следующего занятия.

**Q: У меня ошибка при push: "failed to push some refs"**
A: Скорее всего, кто-то уже обновил `develop`, а ваша ветка устарела. Делаем:
```bash
git pull origin develop
# Решаем конфликты, если они есть
git push origin feature/lesson1-...
```

**Q: Как выбрать лида команды?**
A: Обсудите в команде. Лид не обязательно самый сильный программист, а тот, кто готов координировать, общаться со мной и другими командами, следить за сроками.
