# Инструкция для участников команды Don't Starve Lite

## Привет, команда! 👋

Я ментор этого проекта. Мы начинаем большое и интересное путешествие — создание собственной игры! Чтобы всё прошло гладко, нам нужно с самого начала настроить процессы и инструменты. Этот документ — наша настольная книга на ближайшие два занятия.

### Занятие 1: Знакомство, установка, первый коммит
**Цель:** Стать частью проекта, настроить окружение, сделать первый вклад

### Занятие 2: Основы Git, canvas, первый рисунок
**Цель:** Научиться работать в команде через Git и увидеть первый визуальный результат

---

# Занятие 1: Становимся контрибьюторами

## Подготовка (до начала занятия)

### Что нужно сделать ментору заранее:
- [ ] Создать организацию на GitHub (если ещё нет)
- [ ] Создать репозиторий `dont-starve-lite` в организации
- [ ] Инициализировать репозиторий с начальной структурой:
  ```
  dont-starve-lite/
  ├── index.html
  ├── style.css
  ├── js/
  │   └── main.js
  ├── assets/
  │   ├── images/
  │   └── sounds/
  ├── data/
  └── README.md
  ```
- [ ] Настроить защиту ветки `main` (Settings > Branches):
  - [ ] Require a pull request before merging
  - [ ] Require 1 approval
- [ ] Создать доску проекта (Projects):
  - Название: "Don't Starve Lite Development"
  - Шаблон: "Basic Kanban"
  - Колонки: To do, In progress, Review, Done
- [ ] Создать файл `CONTRIBUTING.md` (шаблон ниже)
- [ ] Создать метки (labels) для issues:
  - `team: core`, `team: ui`, `team: ai`, `team: graphics`, `team: sound`, `team: qa`
  - `priority: high`, `priority: medium`, `priority: low`
  - `type: bug`, `type: feature`, `type: chore`

### Шаблон CONTRIBUTING.md
```markdown
# Как вносить вклад в проект

## Ветки
- `main` — только стабильные версии (защищена)
- `develop` — основная ветка разработки
- `feature/*` — ветки для новых задач (например, `feature/core-hello`)

## Коммиты
Пишем осмысленные сообщения на английском:
- `feat: add player movement` — новая функция
- `fix: correct health bar position` — исправление бага
- `docs: update README` — документация

## Pull Requests
1. Создаёте ветку от `develop`
2. Выполняете задачу
3. Открываете PR в `develop`
4. В описании PR указываете: "Closes #номер_issue"
5. Ждёте ревью (минимум 1 одобрение)
6. Ментор мёржит

## Code Review
- Будьте вежливы
- Проверяйте, что код работает
- Ищите потенциальные проблемы
- Предлагайте улучшения
```

## Ход занятия 1 (90 минут)

### 05 мин: Организационный момент

**Я говорю:**
> "Привет всем! Рад видеть. Сегодня важный день — мы начинаем строить нашу игру. Но прежде чем писать код, нам нужно настроить всё окружение и понять, как мы будем работать вместе. Представьте, что мы — маленькая игровая студия, и у нас есть продюсер (я), тимлиды и разработчики."

### 20 мин: Теория — погружение в проект

#### Часть 1. Что мы строим (5 мин)

Показываю слайд или открываю картинку Don't Starve.

> "Мы создаём упрощённую веб-версию игры Don't Starve. Называется Don't Starve Lite. Вот ключевые механики, которые должны работать через 30 занятий:"
> - Процедурно генерируемая карта (лес, трава, камни)
> - Персонаж, которым можно ходить (клавиши WASD)
> - Ресурсы, которые можно собирать (деревья, камни, ягоды)
> - Инвентарь и крафт (топор, кирка, факел)
> - Враги (паук, гончая), которые нападают
> - Полоски голода и здоровья

#### Часть 2. Командная структура (5 мин)

> "Мы делимся на 6 команд. У каждой своя зона ответственности. Внутри команды вы выбираете лида — он будет координировать работу и участвовать в синхронизациях."

| Команда | Кто отвечает |
|---------|--------------|
| **Core Mechanics** | Классы игрока, ресурсов, врагов, физика сбора и атак |
| **Game State & UI** | Инвентарь, полоски голода/здоровья, интерфейс крафта |
| **AI & Balance** | Поведение врагов, баланс ресурсов и голода |
| **Assets & Graphics** | Спрайты (персонаж, ресурсы, враги), иконки |
| **Sound & Effects** | Звуки окружения, сбора, атак; визуальные эффекты |
| **Integration & QA** | Генерация карты, Git, сборка, деплой, тестирование |

#### Часть 3. GitHub Flow (10 мин)

Открываю репозиторий на экране и показываю:

> "Весь наш код будет жить вот здесь. Давайте разберём, как мы будем работать:"
> 
> **Ветки:**
> - `main` — это наша "золотая" ветка. Здесь только идеальный, оттестированный код. Никто не коммитит сюда напрямую.
> - `develop` — ветка разработки. Сюда сливаются все новые фичи.
> - `feature/название` — ваши личные ветки. От каждой задачи — своя ветка.
>
> **Процесс:**
> 1. Вы берёте задачу (issue)
> 2. Создаёте ветку от `develop`: `feature/что-делаем`
> 3. Пишете код
> 4. Открываете Pull Request в `develop`
> 5. Другой разработчик (не из вашей команды) проверяет код
> 6. Я (ментор) смотрю и мёржу

### 10 мин: Формирование команд и выбор лидов

> "Сейчас мы разделимся на команды. Я буду называть команду, и вы поднимаете руку, если хотите туда."

Процесс:
1. Зачитываю список команд из таблицы
2. Студенты выбирают
3. В каждой команде прошу выбрать лида (можно добровольно или назначаю, если никто не хочет)
4. Записываю лидов в отдельный файл для себя

**Важно:** Слежу, чтобы команды были примерно равны по размеру (рекомендуемые размеры в документе).

### 50 мин: Практика — первый коммит

> "А теперь самое интересное. Каждый из вас сделает свой первый вклад в проект. Задача простая, но важная — она научит нас работать с Git и GitHub. Слушайте внимательно, я буду давать команды по шагам."

#### Шаг 1. Настройка Git (5 мин)

**Я даю команду:**
> "Убедитесь, что Git установлен и настроен. Если нет — делаем сейчас:"

```bash
# Проверяем, есть ли Git
git --version

# Если нет — идём на git-scm.com и качаем

# Настраиваем имя и email (они будут в коммитах)
git config --global user.name "Ваше Имя"
git config --global user.email "ваш@email.com"
```

#### Шаг 2. Клонирование репозитория (3 мин)

> "Теперь каждый клонирует репозиторий к себе на компьютер."

```bash
# Переходим в папку, где будут проекты
cd ~/Documents  # или любая другая

# Клонируем (ссылку я дам в чате)
git clone https://github.com/имя-организации/dont-starve-lite.git

# Заходим в проект
cd dont-starve-lite

# Смотрим, что ветка сейчас main
git branch

# Переключаемся на develop (её пока нет локально, но мы её создадим)
git checkout -b develop origin/develop
# Если ошибка — значит develop есть только на GitHub, делаем так:
git fetch origin
git checkout -b develop origin/develop
```

#### Шаг 3. Создаём свою ветку (2 мин)

> "Теперь каждый создаёт ветку для своего задания. Называем её по правилу: `feature/команда-что-делаем`. Например: `feature/core-hello`."

```bash
# Убеждаемся, что мы в develop и он обновлён
git checkout develop
git pull origin develop

# Создаём свою ветку
git checkout -b feature/название-команды-hello

# Пример для Core Mechanics
git checkout -b feature/core-hello
```

#### Шаг 4. Выполняем задание (30 мин)

> "Теперь открываем редактор кода (VS Code) и делаем то, что написано в задании для вашей команды. Я сейчас раздам задания."

**Задания для команд (раздаю каждому листу или пишу в чат):**

##### Команда Core Mechanics
**Файл:** `js/core.js`
**Код:**
```javascript
function helloCore() {
    console.log("Core Mechanics ready");
}
```
**Действия:**
1. Создать папку `js`, если её нет
2. Создать файл `core.js` внутри `js`
3. Вставить код
4. Открыть `index.html` и после строки `<script src="js/main.js"></script>` добавить:
   ```html
   <script src="js/core.js"></script>
   ```
5. Открыть `js/main.js` и в самом конце добавить:
   ```javascript
   helloCore();
   ```

##### Команда Game State & UI
**Файл:** `js/ui.js`
**Код:**
```javascript
function helloUI() {
    console.log("UI ready");
}
```
**Действия:**
1. Создать файл `js/ui.js`
2. Вставить код
3. В `index.html` подключить `ui.js` **после** `main.js`
4. В `main.js` вызвать `helloUI();`

##### Команда AI & Balance
**Файл:** `js/ai.js`
**Код:**
```javascript
function helloAI() {
    console.log("AI ready");
}
```
**Действия:**
1. Создать файл `js/ai.js`
2. Вставить код
3. В `index.html` подключить `ai.js`
4. В `main.js` вызвать `helloAI();`

##### Команда Assets & Graphics
**Задание:** Создать заглушку для графики
**Действия:**
1. Создать папку `assets/images/`
2. Создать простую картинку (можно в Paint нарисовать квадрат 64x64) или скачать любую иконку
3. Сохранить как `placeholder.png` в `assets/images/`
4. В `index.html` после скриптов добавить:
   ```html
   <img src="assets/images/placeholder.png" alt="placeholder" style="display:none;">
   ```

##### Команда Sound & Effects
**Задание:** Подготовить звуковую заглушку
**Действия:**
1. Создать папку `assets/sounds/`
2. Найти короткий звук (можно с [freesound.org](https://freesound.org/) или использовать стандартный звук Windows)
3. Сохранить как `click.mp3` в `assets/sounds/`
4. В `index.html` добавить:
   ```html
   <audio id="testSound" src="assets/sounds/click.mp3" preload="auto"></audio>
   ```

##### Команда Integration & QA
**Задание:** Координация и проверка
**Действия:**
1. Помочь каждому участнику проверить настройки Git и SSH-ключи
2. Создать файл `CONTRIBUTING.md` (я дам шаблон)
3. Убедиться, что все задания выполнены и не вызывают ошибок
4. После выполнения всех задач проверить в браузере, что в консоли (F12) видны все 6 приветствий

#### Шаг 5. Коммит и пуш (5 мин)

> "Задание сделали? Теперь отправляем его на GitHub."

```bash
# Смотрим, какие файлы изменились
git status

# Добавляем все изменения в коммит
git add .

# Делаем коммит (пишем осмысленное сообщение)
git commit -m "feat: add hello function for [название команды]"

# Отправляем на GitHub
git push origin feature/название-команды-hello
```

#### Шаг 6. Открываем Pull Request (5 мин)

> "Теперь идём на GitHub и открываем Pull Request."

**Инструкция на экране:**
1. Заходим в репозиторий на GitHub
2. Видим жёлтую плашку "feature/... had recent pushes" — нажимаем "Compare & pull request"
3. Проверяем:
   - Base: `develop`
   - Compare: `feature/...`
4. Заголовок: "feat: add hello function for [команда]"
5. Описание: "Closes #номер_issue (если issue создавали)"
6. Нажимаем "Create pull request"

### 05 мин: Подведение итогов

> "Поздравляю! Вы только что сделали свой первый вклад в проект. Теперь:
> - Я посмотрю ваши PR и смерджу их
> - После мержа все обновят свою ветку `develop`
>
> **Домашнее задание:**
> 1. Тем, кто не успел — доделать PR сегодня
> 2. Всем прочитать `CONTRIBUTING.md`, который создала команда Integration & QA
> 3. Подумать, какая команда чем будет заниматься дальше"
